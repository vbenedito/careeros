# Landing page (LAND)

Status: **Approved** (product owner, design 2026-11-11) · Issue #101 (parent #102) · Plans: [`docs/landing/`](../../docs/landing/) · Decision: [ADR-0009](../../docs/adr/0009-landing-route-and-rendering.md)

Amended 2026-11-11 (#131): LAND-01 proxy, LAND-04 site URL fallback, LAND-06 full CSP, to match the code. Amended 2026-11-11 (#135): LAND-09 Search Console verification. Amended 2026-11-11 (#137): LAND-01 and LAND-06 allow the Vercel Web Analytics script ([ADR-0010](../../docs/adr/0010-web-analytics.md)); privacy "Never" list wording.

A public page that explains CareerOS to people preparing for technical interviews, leads with their problem, and shows the product working. Everything it claims matches specs/v0.

- **LAND-01** `/` serves the landing page to signed-out visitors. It is public (exact match), static (built once) and has no JavaScript of its own (only the analytics script of LAND-06, when enabled). The proxy (`apps/web/proxy.ts`) still runs on `/`: it refreshes session cookies and redirects signed-in visitors (LAND-02), but does not set its nonce CSP on the landing response.
- **LAND-02** A signed-in visitor at `/` is redirected to `/dashboard`, the query string kept. The dashboard lives at `/dashboard`; sign-in, `/sign-in` while signed in and unsafe `next` values lead there.
- **LAND-03** Content follows `docs/landing/content.md` and the approved design: hero with the live tab demo (in browser chrome, over a dot grid), a belt of example study sites, the problem, a bento grid of the three interactive cards ("Stop starting timers", "Stop counting the scroll as study", "See the week you really had"), privacy, how it works (steps beside an example engine log whose lines each match a TRK/SYNC rule), the rules in numbers, FAQ, final call to action, footer. Sample data only, and its totals add up.
- **LAND-04** SEO (`docs/landing/seo.md`): title ≤ 60 characters led by "study time tracker", description ≤ 155, one `h1`, canonical from `SITE_URL` (at build time, when it is not set: `https://$VERCEL_PROJECT_PRODUCTION_URL`, then `http://localhost:3000`; `buildSiteUrl` in `lib/env.ts`), `lang="en"`, Open Graph and Twitter tags, JSON-LD (`WebSite`, `Organization`, `SoftwareApplication` with `BrowserApplication`, free, no ratings).
- **LAND-05** Calls to action: "Get started — it's free" → `/sign-in`; "Add to Chrome" → `EXTENSION_INSTALL_URL` (https only; until it is set, the Chrome Web Store search). The landing page launches publicly once the store listing exists (product owner).
- **LAND-06** Security: the landing response carries its own CSP (`lib/landing/csp.ts`): `default-src 'none'`; `script-src 'none'`; `style-src 'sha256-…'` (the one inline stylesheet, by hash); `style-src-attr 'unsafe-inline'` (style attributes cannot run code, as in SEC-09); `img-src 'self' data:`; `font-src 'self'`; `base-uri 'none'`; `form-action 'none'`; `frame-ancestors 'none'`; `upgrade-insecure-requests` when the site URL is https. The static security headers (SEC-09) apply as everywhere. The only `<script>` is the JSON-LD data block. Amended 2026-11-11 (#137): when Web Analytics is enabled (SEC-15: production deployments on Vercel, decided at build time) the page also loads `<script defer src="/_vercel/insights/script.js">`, and the CSP changes `script-src` to exactly that URL on the site origin (`script-src https://<site>/_vercel/insights/script.js`) and adds `connect-src https://<site>/_vercel/insights/`; still no inline script and no `'unsafe-inline'`. The privacy section's "Never" list says "Ad trackers or cookies". Fonts are self-hosted (`font-src 'self'`; Mona Sans, SIL OFL 1.1, for headings). No third-party requests (SEC-15).
- **LAND-07** Search files: `/robots.txt` (disallows `/api/` and `/auth/` only), `/sitemap.xml` (`/` and `/privacy`), `/opengraph-image` (1200×630, built at build time) and `/icon.svg` (the extension's icon, the favicon of every page), all public. App pages are `noindex`; `/privacy` is indexable.
- **LAND-08** Interactions use native checkboxes and radio buttons styled with CSS (step away, pick study sites, week/month), each with a label, reachable by keyboard. Motion is CSS only, runs only when the visitor has not asked for reduced motion, and a "Pause animations" control stops it (WCAG 2.2.2).
- **LAND-09** Search Console: when `GOOGLE_SITE_VERIFICATION` is set at build time, the landing page carries `<meta name="google-site-verification" content="…">` (Google's URL-prefix property for the site origin). The value is public; only `[A-Za-z0-9_-]{20,100}` is accepted, otherwise the build fails. Unset: no tag. Bing Webmaster Tools imports the site from Search Console.

**Implementation note (2026-11-11):** the static page is a Next.js route handler at `/` (`app/route.ts`, `dynamic = "force-static"`) returning the HTML from `lib/landing/page.ts`, rather than a separate prebuild step and rewrite. It is the same decision as ADR-0009 (static, no JavaScript, its own CSP) in one response. The page is dark only, as in the approved design.
